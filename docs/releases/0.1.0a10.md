# RankProbe 0.1.0a10

想在 CI 里检查“这次 MRR 是否比固定基线下降太多”？这版可以加一条你事先声明的容忍规则。先固定基线、标签、协议和门槛，再比较新导出；结果会说明是通过、下降超限，还是比较条件不足。无论后两种情况哪一种，完整报告都会先保存，方便回头核查。

## 下载和使用

- **`RankProbe-0.1.0a10.zip`**：推荐首次使用，含离线 wheel、对应源码、示例和 `START_HERE.md`。完整解压后从这里开始。
- `rankprobe-0.1.0a10-py3-none-any.whl`：Python 3.10+ 的可安装核心，包含这项可选检查。
- `rankprobe-0.1.0a10.tar.gz`：源码分发包，含说明、检查和原始小样例。
- `RELEASE_INFO.json` 与 `SHA256SUMS`：核对源码提交、文件大小和摘要。完整 ZIP 内另有逐文件清单；旧版、旧输入和旧报告请单独保留。

## 加规则前，先看这些条件

按 [MRR 检查步骤](https://github.com/C4LLM3LUC4S/rankprobe/blob/v0.1.0a10/docs/mrr-regression.md)一起提供 `--max-mrr-drop mrr@K=DROP`、`--min-guard-queries N` 和已保存的 `--guard-baseline-sha256 HEX`。第一份输入是基线，第二份是新结果；不加这三个参数，普通 `compare` 的行为保持不变。源码预览入口 `quickstart.py` 不提供这三个选项，请使用完整 CLI。

双方必须使用相同的全部查询、候选和已解析标签，且所选 MRR 能覆盖双方全部查询。缺失标签仍是未知；不可算值、比较范围不足、基线摘要不符或补零假设都会阻止这条严格规则通过。首个相关项已经由已知标签确定时，排在它之后的未知仍可保留。详见 [指标语义](https://github.com/C4LLM3LUC4S/rankprobe/blob/v0.1.0a10/docs/metrics.md)。

`failed_drop` 和 `blocked` 会在保存 HTML/JSON 后返回 1，`--fail-on never` 也不会绕过已声明的规则。输入、参数或保存失败仍返回 2。按 [CI 保留报告说明](https://github.com/C4LLM3LUC4S/rankprobe/blob/v0.1.0a10/docs/local-ci.md)保存失败证据，再修正问题，不能为了通过而临时换基线、删查询或提高门槛。

基线摘要只自动核对那份文件；本次标签来源摘要与协议会保存在报告里，仍需在自己的 CI 中另外固定和检查。容忍值是任务负责人给出的绝对分数规则，不是相对百分比、显著性检验、来源认证或模型质量证明。

这版还把已发行的整数精度和小增益数值修正写清楚，没有再次改变指标公式。仍是 **alpha 预发行**：开发者小样例和安装检查不代表独立采用或人工节时。所有旧发行保持原样，没有 PyPI 或云部署。

## English

Add an optional, predeclared MRR drop rule to a fresh comparison of a pinned baseline and one new export. Use all three flags in the [installed CLI guide](https://github.com/C4LLM3LUC4S/rankprobe/blob/v0.1.0a10/docs/mrr-regression.md); the source-preview launcher does not expose these options. The check requires identical complete query/candidate/resolved-label populations and fully eligible MRR queries. Unknown judgments stay unknown. Missing, restricted or assumption-filled results cannot become a pass merely by meeting a minimum count.

Completed reports retain `pass`, `failed_drop` or `blocked`, the rule and a separate guard-module source hash. Failed or blocked checks exit 1 even with `--fail-on never`; argument, input or output failure exits 2. Plain comparisons and the existing metric formulas are unchanged. The legacy nine-module identity schema and inventory remain the same; actual hashes identify the current file bytes. The additional decision module is checked separately.

Only the supplied baseline digest is automatically pinned. Freeze and check the actual judgments, protocol and acceptance rule separately before inspecting the candidate. An absolute tolerance is an engineering requirement, not a significance test, intended-benchmark certification or model-quality guarantee. Keep the matching source and reports using the [recovery guide](https://github.com/C4LLM3LUC4S/rankprobe/blob/v0.1.0a10/docs/source-recovery.md). This GitHub **alpha prerelease** makes no claim of independent adoption or measured human benefit.
