# RankProbe 0.1.0a7

这版主要处理保存报告时的两个麻烦：保存位置不能用，却等计算完才报错；覆盖旧报告失败后，原文件又暂时放不回去。现在会尽早检查保存位置，无法恢复到原处的旧文件会留在备份目录，并在终端说明去哪找。

## 下载和开始使用

- **`RankProbe-0.1.0a7.zip`**：推荐首次使用。包含离线安装包、对应源码、原创示例和 `START_HERE.md`。
- `rankprobe-0.1.0a7-py3-none-any.whl`：在已有 Python 3.10+ 独立环境中安装。
- `rankprobe-0.1.0a7.tar.gz`：源码分发包。
- `RELEASE_INFO.json` 和 `SHA256SUMS`：核对源码提交、文件大小和 SHA-256。

完整解压 ZIP，在下载目录用 `(Get-FileHash .\RankProbe-0.1.0a7.zip -Algorithm SHA256).Hash` 核对同名校验条目。包内 `BUILD_INFO.json` 标明源码，`MANIFEST.json` 用于核对解压内容。旧版本请单独保留。

## 这版改了什么

- 输出已存在，或上级路径是文件时，在读取输入和计算报告前停下。免安装入口也会给出换新目录的提示，保留旧文件。
- 显式覆盖报告时，若新报告保存失败且旧文件无法全部放回原处，继续尝试其余恢复，并保留尚未恢复的原文件。看到 **Backups retained** 后，按[备份恢复说明](../source-recovery.md#覆盖报告时保存失败了)复制原文件到新目录。
- 完整报告已保存、只是备用文件暂时删不掉时，保留备用文件并提示，不把已完成的报告误报为失败。

这些修复通过了受控文件错误和安装后恢复检查；没有声称发生过外部用户数据丢失，也不能保证磁盘损坏或突然断电后的恢复。原始导出、命令和对应源码仍应一起保留。输入、指标、未知标签及报告 JSON 的含义没有改变。

## 用自己的结果验收

按[发现问题、处理、再检查](../case-actions.md)查看一份导出：从报告中的查询编号回到原文件，确认查询、候选和标签范围，再用新目录复核。警告消失不等于模型变好。没有标签仍是未知，无法计算也不是零分。

## English

This maintenance alpha checks unusable output paths before loading inputs or computing reports. If an explicit overwrite fails and rollback cannot restore every original, remaining originals stay in a retained backup directory with an actionable path. Cleanup locks do not invalidate a completed report. Input parsing, metrics, unknown-label semantics and report JSON are unchanged.

Use the complete `RankProbe-0.1.0a7.zip` with Python 3.10+, or install the wheel in an isolated environment. Check `SHA256SUMS`, keep the matching source and follow [source and report recovery](../source-recovery.md). Recovery checks use authored fixtures and controlled I/O failures; they do not certify recovery from storage corruption or establish independent adoption, model quality or human time saved.

Earlier alpha releases and the course repository remain available. This is an **alpha prerelease** distributed through GitHub; PyPI and cloud deployment are not part of it.
